# 백엔드 — Google Apps Script + 스프레드시트

블로그의 회원·게시글을 구글 스프레드시트에 저장한다.
`Code.gs` 하나가 JSON API 역할을 하고, 프론트엔드의 `js/store.js`가 이 API만 호출한다.

- 스프레드시트: https://docs.google.com/spreadsheets/d/1yNRhBwuq2ouszyKy3uGm3cZmIcSlyJIZK7nnfD6Cn7w/edit
- Apps Script 프로젝트: https://script.google.com/d/1sL1M2J6ucQwX78C6LT50ho076fnCCOFXnU5_sQYISnWlwMaNs0dgT-zg/edit

## 파일

| 파일 | 언제 쓰나 |
|---|---|
| `step1-auth.gs` | **1단계.** 회원가입·로그인만. 배포가 되는지 먼저 확인할 때 |
| `Code.gs` | **2단계.** 게시글까지 포함한 완성본 |

`Code.gs`는 `step1-auth.gs`의 상위 집합이다. 1단계에서 가입한 회원과 시트는
2단계로 넘어가도 **그대로 유지된다.** 나중에 편집기 내용을 `Code.gs`로 바꾸고
다시 배포하기만 하면 된다.

# 1단계 — 회원가입 / 로그인

## 1. 코드 붙여넣기

Apps Script 편집기를 열고 `Code.gs`의 내용을 **전부 지운 뒤** 이 폴더의 `step1-auth.gs`를 붙여넣는다.
`SHEET_ID`는 이미 채워져 있다.

## 2. `setup()` 실행 — 선택 사항

**시트는 첫 요청 때 자동으로 만들어진다.** `sheet()`가 없는 시트를 발견하면
헤더까지 갖춰 직접 생성하므로, `setup()`을 실행하지 않아도 가입·로그인·글쓰기가 동작한다.

`setup()`을 실행하면 여기에 더해 **데모 계정과 예시 글**이 들어간다.
편집기 상단의 함수 선택 상자에서 **`setup`** 을 고르고 **실행**을 누른다.

- 처음 실행하면 권한 승인 창이 뜬다. *고급 → 안전하지 않은 페이지로 이동* 을 거쳐 승인한다.
  (본인이 만든 스크립트라 나오는 경고다)
- 여러 번 실행해도 데이터가 중복되지 않는다.
- 잘 안 되면 **`diagnose()`** 를 실행한다. 시트 상태를 진단하고 필요하면 `setup()`까지 대신 돌린다.

## 3. `testAuth()` 실행 — 배포 전에 코드부터 확인

함수 선택에서 **`testAuth`** 를 고르고 실행한 뒤, **실행 로그**(`Ctrl+Enter`)를 본다.

```
전부 통과 (19건). 이제 [배포 > 새 배포 > 웹 앱]으로 배포하세요.
  통과  users 시트가 있다
  통과  짧은 닉네임을 막는다
  …
```

가입·로그인·토큰·중복 검사·해시 저장까지 한 번에 확인한다.
점검용으로 만든 계정과 세션은 **끝나고 스스로 지운다.**

이 단계를 먼저 하는 이유는 문제를 나누기 위해서다.

| 상황 | 원인 |
|---|---|
| `testAuth()`가 실패 | 코드나 시트 문제 |
| `testAuth()`는 통과하는데 브라우저에서 실패 | 배포 설정 또는 CORS 문제 |

## 4. 웹 앱으로 배포

**배포 → 새 배포 → 유형: 웹 앱**

| 항목 | 값 |
|---|---|
| 설명 | 아무거나 (예: v1) |
| 실행 계정 | **나** |
| 액세스 권한 | **모든 사용자** |

> "모든 사용자"가 아니면 브라우저가 JSON 대신 구글 로그인 페이지를 받아서
> `서버 응답을 이해할 수 없습니다` 오류가 난다.

배포하면 이런 주소가 나온다:

```
https://script.google.com/macros/s/AKfycb................/exec
```

## 5. 주소를 브라우저에 그냥 붙여넣어 본다

`/exec` 주소를 주소창에 그대로 입력하면 이렇게 나와야 한다:

```json
{"ok":true,"message":"연결됐습니다. 1단계(회원가입·로그인) 서버가 살아 있습니다.","actions":[...]}
```

| 대신 나온 것 | 뜻 |
|---|---|
| 구글 로그인 페이지 | 액세스 권한이 "모든 사용자"가 아니다 |
| `승인이 필요합니다` | 배포할 때 실행 계정이 "나"가 아니다 |
| `스크립트 함수를 찾을 수 없습니다: doGet` | 붙여넣기가 덜 됐거나 저장을 안 했다 |
| `~ 시트가 없습니다` | 옛 버전이 배포돼 있다. **배포 관리 → 새 버전**으로 다시 배포한다 |

## 6. 프론트엔드에 주소 넣기

`js/config.js` 한 줄만 고친다.

```js
var BLOG_API_URL = 'https://script.google.com/macros/s/AKfycb....../exec';
```

## 7. GitHub Pages로 배포

**`file://`로 열면 동작하지 않는다.** `file://`의 출처는 `null`이라 브라우저가 요청을 CORS로 막는다.

저장소 **Settings → Pages → Source: main 브랜치 / 루트** 로 켜면
`https://yjyj511-gif.github.io/0901/` 에서 열린다.

로컬에서 확인할 때도 파일을 직접 열지 말고 서버로 띄운다:

```bash
python -m http.server 8000
# http://localhost:8000
```

## 8. 확인할 것

- `signup.html` 에서 가입 → **스프레드시트 `users` 시트에 행이 늘어난다**
- 같은 닉네임으로 다시 가입 → 닉네임 칸 아래에 "이미 사용 중인 닉네임입니다"
- `login.html` 에서 **데모 계정 채우기** → 로그인 → 헤더가 *글쓰기 · 프로필 · 로그아웃* 으로 바뀐다
- 새로고침해도 로그인이 유지된다 (`sessions` 시트의 토큰 덕분)
- 목록 페이지는 "아직 작성된 글이 없습니다" — 1단계에는 게시글이 없으니 정상이다

여기까지 되면 **배포·CORS·인증이 전부 검증된 것**이다.

# 2단계 — 게시글

편집기 내용을 `Code.gs` 전체로 바꾸고, `setup()` 을 한 번 더 실행한 뒤
**배포 관리 → 새 버전**으로 다시 배포한다.

- `posts` 시트가 추가되고 예시 글 3편이 들어간다
- 1단계에서 가입한 회원과 세션은 **그대로 남는다**
- `/exec` 주소가 바뀌지 않으므로 `js/config.js` 는 고칠 필요가 없다

## 코드를 고친 뒤에

**저장만 하면 반영되지 않는다.** 이전 버전이 계속 서빙된다.

**배포 → 배포 관리 → (연필 아이콘) → 버전: 새 버전 → 배포**

이렇게 하면 `/exec` 주소는 그대로 유지되므로 `config.js`는 다시 고칠 필요가 없다.
"새 배포"를 누르면 주소가 바뀌니 주의한다.

## API

모든 응답은 `{ ok: true, ... }` 또는 `{ ok: false, field?, message }` 형태다.

| action | 방식 | 설명 |
|---|---|---|
| (없음) | GET | 주소만 열면 연결 확인용 응답 (1단계) |
| `bootstrap` | GET | 글 전체 + 내 정보. 페이지가 뜰 때 한 번 호출 |
| `signup` | POST | 가입. 성공 시 토큰까지 발급 |
| `login` | POST | 이메일 또는 닉네임으로 로그인 |
| `logout` | POST | 세션 삭제 |
| `createPost` / `updatePost` / `deletePost` | POST | 글 쓰기·고치기·지우기 (본인 글만) |
| `incrementViews` | POST | 조회수 +1 |
| `updateUser` / `changePassword` | POST | 프로필·비밀번호 |

### POST는 반드시 `text/plain`

Apps Script는 브라우저가 보내는 **OPTIONS 프리플라이트를 처리하지 못한다.**
응답에 CORS 헤더를 아무리 넣어도 소용없다 — 프리플라이트가 먼저 실패해서
`doPost`가 아예 실행되지 않기 때문이다.

그래서 `Content-Type: text/plain;charset=utf-8` 로 보낸다. "단순 요청"이라 프리플라이트가 없다.
내용은 그대로 JSON이고, 서버에서 `JSON.parse(e.postData.contents)` 로 읽는다.

## 보안 — 읽고 넘어가기

**이 API는 공개다.** 주소가 프론트엔드 코드에 들어 있어 누구나 소스를 보고 직접 호출할 수 있다.

지금 되어 있는 것:

- 비밀번호는 솔트를 섞어 SHA-256으로 해시하며, 원문은 어디에도 저장되지 않는다
- 솔트는 시트가 아니라 스크립트 속성(Script Properties)에 있다
- 해시는 클라이언트로 절대 내려가지 않는다
- 글 수정·삭제는 토큰 주인이 작성자일 때만 통과한다
- 남의 프로필을 볼 때는 이메일이 빠진다

그래도 **실제로 쓰는 비밀번호는 넣지 말 것.** 학습용·포트폴리오용으로는 충분하지만
그 이상은 아니다.

## 알아 둘 제약

| 항목 | 내용 |
|---|---|
| 실행 시간 | 개인 계정 기준 하루 약 90분 |
| 동시 실행 | 30개 |
| 응답 속도 | 첫 호출은 1~3초 걸릴 수 있다 (콜드 스타트) |
| 글 수 | `bootstrap`이 글 전체를 내려주므로 수백 편이 넘어가면 느려진다 |

글이 많아지면 `bootstrap`에서 본문을 빼고 목록용 요약만 내려주도록 바꾸면 된다.

## 유지보수

- `cleanupSessions()` — 만료된 세션 행을 지운다.
  **트리거 → 트리거 추가 → cleanupSessions / 시간 기반 / 일 단위** 로 걸어 두면 자동으로 돈다.
- 시트를 직접 고쳐도 된다. 다만 **1행(헤더)과 A열(id)은 건드리지 말 것** — 코드가 그 둘을 기준으로 찾는다.
